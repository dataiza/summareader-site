SummaReader

Ein Reader, der abruft, was Sie verfolgen — Feeds, Artikel, YouTube, Mastodon, Nostr —, es zusammenfasst und das Ergebnis auf allen Ihren Geräten gleich hält.

  • Ihre Bibliothek liegt auf Ihren Geräten. Wir betreiben keinen Server, der sie empfängt.
  • Zusammenfassungen entstehen standardmäßig auf diesem Gerät, sobald Sie ein Modell laden. Sie können sie stattdessen an Ihren eigenen Server oder eine Cloud-API schicken; dann geht der Text des Artikels dorthin. Auch anderes verbindet sich nach außen — der unsichtbare Seiten-Renderer, Hugging Face, die Update-Prüfung, die Systemsicherung des Telefons, die lokalen Server —, und die Datenschutzerklärung nennt sie alle.
  • Die Synchronisierung ist Ende-zu-Ende-verschlüsselt: Der Server hält Chiffretext unter Sequenznummern und kann nichts davon lesen.

Es gibt keine Zusammenfassung auf dem Server, keine Suche auf dem Server und keinen Web-Reader. Das sind keine fehlenden Funktionen; sie folgen aus dem ersten Punkt.

Was Sie einfügen können

Tippen Sie auf + neben Ihr Regal und fügen Sie eine Adresse ein. Es passiert das Richtige:

Sie fügen einDaraus wird
Eine Feed-Adresse (…/feed.xml, …/rss)Ein Feed
Die Startseite einer WebsiteEin Feed, wenn die Seite einen anbietet
Eine YouTube-Kanal- oder VideoadresseDieser Kanal
Ein Mastodon-Konto (@name@server)Die Beiträge dieses Kontos
Jede andere SeiteDie Seite selbst, einmal gespeichert

Wer von einem anderen Reader kommt: Einstellungen › Erweitert › Ihre Daten › Import nimmt eine OPML-Datei, und alles darin kommt als Quelle an.

Wo Zusammenfassungen entstehen

Zusammenfassungen entstehen standardmäßig auf diesem Gerät, aber beim ersten Start wird kein Modell geladen. Der Reader funktioniert ganz ohne Sprachmodell, bis Sie eines laden oder Ihren eigenen Server oder eine Cloud-API einrichten.

Wie es funktioniert

Ein Eintrag, eine Identität

Die ID eines Eintrags ist ein Hash seiner kanonischen URL. Derselbe Artikel, der aus einem Feed, aus einer Freigabe und über einen Mastodon-Link kommt, ist also ein Eintrag, der unter jeder Quelle erscheint. Deshalb ist auch das Zusammenführen zweier Geräte eine Vereinigungsmenge und kein Abgleichproblem.

Zusammenfassungen werden zerlegt, verarbeitet und zusammengeführt

Lange Transkripte werden mit einem echten Tokenizer auf ein Prefill-Budget zerlegt, nicht mit chars / 4 — gemessen unterschätzt diese Faustregel Slowakisch um etwa 43 % und Tschechisch um etwa 51 %, was den Kontext überlaufen lässt und die Antwort des Modells abschneidet.

Die Aufbewahrung hat zwei Stufen

Zuerst gehen der extrahierte Text und das Titelbild, was fast den ganzen Platz freigibt, während Metadaten und Zusammenfassungen bleiben; die Adresse des Bildes bleibt erhalten, sodass es beim späteren Öffnen des Artikels neu geladen wird. Einträge gehen später. Was gespeichert, angeheftet, kommentiert ist oder auf eine Zusammenfassung wartet, wird nie gelöscht — Markierungen stammen vom Benutzer und existieren vielleicht nirgends sonst.

Die Synchronisierung ist ein Protokoll verschlüsselter Einträge plus inhaltsadressierte Blobs

Der Server hält Chiffretext unter Sequenznummern und kann nichts davon lesen. Löschungen reisen als ausdrückliche Grabsteine; ein leerer Server löst nie eine lokale Löschung aus, denn ein Server kann aus mehreren Gründen leer sein, und nur einer davon bedeutet, dass etwas gelöscht wurde.

Zwei Dinge seien genannt. Eine Seite, die ihren Text mit Skripten aufbaut, wird einmal unsichtbar in der Web-Engine des Systems geöffnet, und der Text wird aus dem Ergebnis gelesen. Die Skripte der Seite laufen dabei, Tracker eingeschlossen, und die Engine vergisst die Website nach jeder Seite; die Datenschutzerklärung sagt mehr. Und die Größen der Teilstücke sind vorläufig, bis der Prefill-Benchmark auf echter Mobil-Hardware läuft.
